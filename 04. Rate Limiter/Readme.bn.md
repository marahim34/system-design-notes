# অধ্যায় ৪: ডিস্ট্রিবিউটেড রেট লিমিটার ডিজাইন (Design a Rate Limiter)

## ভূমিকা
নেটওয়ার্ক সিস্টেমে রেট লিমিটার (Rate Limiter) হলো এমন এক শক্তিশালী রক্ষাকবচ, যা ক্লায়েন্ট বা কোনো নির্দিষ্ট সার্ভিস থেকে পাঠানো রিকোয়েস্টের সংখ্যা ও গতি কঠোরভাবে নিয়ন্ত্রণ করে। এটি সিস্টেমকে DoS আক্রমণ ও ব্রুট-ফোর্স থেকে বাঁচায়, ক্লাউড বিল নিয়ন্ত্রণে রাখে এবং হঠাৎ ট্রাফিক স্পাইকে ব্যাকএন্ড সার্ভার ক্র্যাশ হওয়া প্রতিরোধ করে।


## রেট লিমিটিংয়ের (Rate Limiting-এর) সুবিধা
- **DOS আক্রমণ প্রতিরোধ:** সার্ভারের মেমোরি বা CPU শেষ হয়ে যাওয়া (Resource Starvation) বা ক্র্যাশ ঠেকাতে অতিরিক্ত কল ব্লক করা।
- **খরচ কমানো:** সার্ভারের খরচ কমাতে অনাকাঙ্ক্ষিত বা অতিরিক্ত অনুরোধ সীমিত করা।
- **অভারলোড প্রতিরোধ করা:** সার্ভারের কর্মক্ষমতা স্থিতিশীল করার জন্য অতিরিক্ত অনুরোধগুলি ফিল্টার করা।

## ধাপ ১: সমস্যা বোঝা
### মূল প্রয়োজনীয় বৈশিষ্ট্য (Core Features)
- সার্ভার-সাইড এপিআই রেট লিমিটার।
- একাধিক থ্রোটল নিয়মের জন্য সমর্থন।
- বিতরণ করা পরিবেশে বড় মাপের সিস্টেম পরিচালনা করুন।
- একটি স্বতন্ত্র পরিষেবা বা অ্যাপ্লিকেশন-স্তরের কোডের বিকল্প।
- থ্রোটল হলে ব্যবহারকারীদের জানান।

### সিস্টেম রিকোয়ারমেন্টস (Requirements)
- সঠিক রিকোয়েস্ট থ্রোটলিং (Request Throttling)।
- ন্যূনতম লেটেন্সি (Minimal Latency)।
- কম মেমরি ব্যবহার।
- বিতরণ ক্ষমতা।
- পরিষ্কার ব্যতিক্রম হ্যান্ডলিং.
- উচ্চ ফল্ট টলারেন্স (High Fault Tolerance)।

## ধাপ ২: উচ্চ-স্তরের নকশা
### কোথায় স্থাপন করবেন? (Placement Options)
<div style="margin-left:2rem">
    <img src="./images/rate_limiter_architecture.png"  alt="Rate Limiting Middleware Architecture" width="550">
</div>

1. **ক্লায়েন্ট-সাইড ইমপ্লিমেন্টেশন:** ক্লায়েন্ট সাইড কখনো নিরাপদ নয়; ইউজার বা অ্যাটাকার সহজেই এটি বাইপাস করতে পারে।
2. **সার্ভার-সাইড ইমপ্লিমেন্টেশন:** সার্ভার সাইডে কন্ট্রোল নিজের হাতে থাকে এবং সিস্টেম নির্ভরযোগ্য হয়।
3. **মিডলওয়্যার (API গেটওয়ে):** মাইক্রোসার্ভিসের ক্ষেত্রে API Gateway-তে রেট লিমিটিং রাখলে আলাদা সার্ভিসের ওপর লোড পড়ে না।


### কোথায় স্থাপন করবেন তার নির্দেশিকা (Placement Guidelines)
- বর্তমান প্রযুক্তিগত স্ট্যাক মূল্যায়ন করুন এবং দক্ষ বিকল্প নির্বাচন করুন।
- ব্যবসার প্রয়োজনের উপর ভিত্তি করে উপযুক্ত অ্যালগরিদম নির্বাচন করুন।
- মাইক্রোসার্ভিস নিযুক্ত হলে একটি API গেটওয়ে ব্যবহার করুন।
- সম্পদ সীমিত হলে বাণিজ্যিক সমাধান বেছে নিন।

## ধাপ ৩: রেট লিমিটিং অ্যালগরিদম
### 1. Token Bucket Algorithm (টোকেন বাকেট অ্যালগরিদম)
<div style="margin-left:2rem">
  <img src="./images/token-bucket.png"  alt="Token Bucket Algorithm" width="550">
</div>

- **কাজের পদ্ধতি (How it works):** নির্দিষ্ট হারে বাকেটে নতুন টোকেন জমা হতে থাকে; প্রতিটি ইনকামিং রিকোয়েস্ট প্রসেস করতে একটি করে টোকেন খরচ হয়।
- **মূল প্যারামিটার (Parameters):** বাকেটের ধারণক্ষমতা বা সাইজ (Bucket Capacity) এবং রিফিল রেট (Refill Rate) (Refill Rate) (Refill Rate)।
- **সুবিধাসমূহ (Pros):** বাস্তবায়ন করা সহজ, মেমরি-দক্ষ, হঠাৎ আসা ট্রাফিক স্পাইক (Traffic Bursts) সমর্থন করে।
- **সীমাবদ্ধতা (Cons):** সতর্ক প্যারামিটার টিউনিং প্রয়োজন।



### 2. Leaking Bucket Algorithm (লিকিং বাকেট অ্যালগরিদম)
<div style="margin-left:2rem">
  <img src="./images/leaking-bucket.png"  alt="Leaking Bucket Algorithm" width="550">
</div>

- **কাজের পদ্ধতি (How it works):** ফিফো সারি ব্যবহার করে একটি নির্দিষ্ট হারে অনুরোধগুলি প্রক্রিয়া করে।
- **সুবিধাসমূহ (Pros):** মেমরি-দক্ষ, স্থিতিশীল বহিঃপ্রবাহ হার।
- **সীমাবদ্ধতা (Cons):** ট্র্যাফিক বিস্ফোরণ সাম্প্রতিক অনুরোধগুলি বিলম্বিত করতে পারে।

## উন্নত বিবেচনা
### পরিবেশিত পরিবেশ
- **চ্যালেঞ্জ:** রেসের অবস্থা, সিঙ্ক্রোনাইজেশন সমস্যা।
- **সমাধান:** রেডিসে লক, লুয়া স্ক্রিপ্ট বা সাজানো সেট ব্যবহার করুন। সিঙ্ক্রোনাইজেশনের জন্য কেন্দ্রীভূত ডেটা স্টোর নিয়োগ করুন।

### কর্মক্ষমতা অপ্টিমাইজেশান
- কম লেটেন্সির জন্য মাল্টি-ডেটা সেন্টার সেটআপ।
- সিঙ্ক্রোনাইজেশনের জন্য ঘটনাগত ধারাবাহিকতা মডেল।

### মনিটরিং
- অ্যালগরিদমের কার্যকারিতা নিশ্চিত করতে এবং প্রয়োজন অনুসারে নিয়মগুলি সামঞ্জস্য করতে নিয়মিত বিশ্লেষণ।
